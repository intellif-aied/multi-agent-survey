Reference · Architecture

AgentTeams 架构速查

把系统拆成“谁保存目标、谁启动容器、谁传消息、谁保存文件”四部分，快速定位代码与故障。

不要求先懂 Kubernetes。下面先写职责，括号中的英文只用于搜索源码。完整解释见名词表。

目标与检查

管理命令 / HTTP API / Worker 配置记录 / 持续检查程序

保存“希望系统是什么样”，并反复检查实际容器是否符合。

cmd/agt → internal/server → api/v1beta1 → internal/controller

容器与执行

Docker/Kubernetes 驱动 / 容器或 Pod / Agent 运行程序

创建运行载体，恢复工作区并启动 OpenClaw、CoPaw 等 Agent 程序。

internal/backend → worker|copaw|hermes|qwenpaw|openhuman

聊天消息

Matrix 用户 / 房间 / 消息

承载任务指派、提问、进度、人工干预和完成通知。

internal/matrix + Provisioner + runtime channel adapter

持久文件

MinIO 或 OSS 对象存储路径

保存配置、技能、记忆、任务说明和大体积产物，容器删除后仍存在。

internal/oss + Deployer + runtime sync loop

源码名称对照

Spec
配置记录中“希望达到什么状态”的部分。
Status
持续检查程序观察并写回的实际状态。
Reconcile
一轮可安全重复的对齐检查。
Provisioner
源码中的身份准备服务，创建聊天、模型网关和存储身份。
Deployer
源码中的工作区生成服务，把 Agent 配置与技能写入对象存储。
Backend
运行环境驱动，把统一创建请求翻译成 Docker 容器或 Kubernetes Pod。
Runtime Adapter
Agent 程序适配层，把统一配置翻译成 OpenClaw、CoPaw 等程序的启动格式。
